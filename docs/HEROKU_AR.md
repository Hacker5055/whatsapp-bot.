# 🖤 دليل Black X: ربط واتساب وتشغيله على Heroku

الشرح ده لمالك رقم واتساب أو شخص عنده إذن صريح باستخدام الرقم. ابدأ بنسخة واحدة فقط؛ تشغيل نسختين بنفس جلسة واتساب ممكن يسبب تعارضًا. **ربط رقمك مش بيحصل تلقائيًا بمجرد رفع الكود**.

## قبل ما تبدأ

- حساب GitHub عليه نسخة من المستودع [Black X](https://github.com/Hacker5055/whatsapp-bot.) بآخر التعديلات، وحساب Heroku فيه وسيلة دفع إن لزم. إذا كان فرع التعديلات غير منشور لـ GitHub، ارفع الفرع وادمجه أولًا أو اختر نفس الفرع من Heroku عند النشر.
- WhatsApp على الرقم المراد تشغيل البوت به، ويفضل رقم منفصل. لازم تقدر تفتح **الإعدادات ← الأجهزة المرتبطة** على الهاتف.
- Heroku Postgres للاحتفاظ بالجلسة. لا تستخدم ملفات `session/` على Heroku: قرص الـ dyno مؤقت، وملفات الربط تضيع بعد إعادة تشغيله. نسخة Black X تحفظ مفاتيح الجلسة مشفرة في قاعدة البيانات؛ ملفات الإعدادات تحفظ كذلك (لكن **بيانات إعدادات المجموعات ليست مشفّرة على مستوى التطبيق**، لذلك احمِ وصول قاعدة البيانات).
- احسب تكلفة **عامل worker واحد + قاعدة Postgres** حسب الأسعار الحالية في لوحة Heroku قبل تأكيد نشر التطبيق. Heroku أوقفت الخطط المجانية للـ dynos وPostgres؛ لا تعتبرها طريقة استضافة مجانية. [خطط قاعدة البيانات الرسمية](https://devcenter.heroku.com/articles/heroku-postgres-plans) و[إعلان توقف الخطة المجانية](https://devcenter.heroku.com/articles/free-dyno-hours).

## الطريقة المقترحة: Heroku CLI + container

هذه الطريقة مناسبة لأن `Dockerfile` يثبت FFmpeg ويحافظ على بيئة Node.js 22؛ `heroku.yml` يعرّف **worker فقط**، وليس web server. ثبّت [Heroku CLI](https://devcenter.heroku.com/articles/heroku-cli)، وسجّل دخولك من متصفحك بنفسك (لا ترسل كلمة السر أو كود الدخول في الدردشة).

1. نزّل نسختك من GitHub على جهازك، ثم افتح مجلد المشروع:

   ```bash
   git clone <رابط_مستودعك_الذي_يحتوي_على_Black_X> black-x
   cd black-x
   heroku login
   ```

   لو محتاج تجربة محلية قبل النشر: `npm ci` ثم `npm test` و`npm run check`. لا تشغّل `npm start` محليًا بجلسة Heroku في نفس الوقت.

2. أنشئ التطبيق واختر stack **container**، ثم أضف قاعدة البيانات (الخطوات دي قد تتطلب تأكيد تكاليف):

   ```bash
   heroku create <اسم-التطبيق-الخاص-بك>
   heroku stack:set container -a <اسم-التطبيق-الخاص-بك>
   heroku addons:create heroku-postgresql:essential-0 -a <اسم-التطبيق-الخاص-بك>
   ```

   قاعدة البيانات تضيف `DATABASE_URL` تلقائيًا؛ **لا تنسخه إلى GitHub**. لو تعذّر provision بسبب الخطة أو التوفر في منطقتك، اختر خطة Postgres متاحة من لوحة Heroku وعدّل الأمر. المزامنة بين مستودعك على GitHub وHeroku container تختلف حسب إعدادات حسابك؛ الدفع للمستودع وحده ليس نشرًا للنسخة العاملة. إذا استخدمت خطوات CLI من جهازك، ادفع نسخة Black X من فرعك بعد رفعها لمستودعك أولًا.

3. اضبط متغيرات التشغيل. رقم مصر الدولي مثال: `2010XXXXXXXX`؛ لا تضع `+` أو `00` أو الصفر المحلي الأول بعد كود الدولة. ضع رقمك الحقيقي بدل القيم التوضيحية:

   ```bash
   heroku config:set BOT_NAME="Black X" BOT_MODE=private \
     OWNER_NAME="اسمي" OWNER_NUMBER="2010XXXXXXXX" \
     SESSION_ID=black-x DATABASE_SSL_REJECT_UNAUTHORIZED=false \
     -a <اسم-التطبيق-الخاص-بك>
   ```

   `OWNER_NUMBER` يحدد هوية المالك في بطاقة الاتصال والميزات الإضافية؛ حساب واتساب المرتبط نفسه يعتبر مالكًا أيضًا. اكتب رقم المالك الدولي فقط، بدون علامة زائد، و**لا تترك أرقامًا وهمية**. اسم `SESSION_ID` يميز الجلسة داخل قاعدة البيانات؛ اتركه ثابتًا ولا تكرر نفس الاسم لتطبيقين يعملان معًا.

4. أنشئ مفتاح تشفير للجلسة على **جهازك**، واحتفظ به في مدير أسرار، ثم أضفه في **Heroku → Settings → Config Vars** باسم `SESSION_ENCRYPTION_KEY` (أو بأمر CLI على جهازك إذا كنت تفهم أثر حفظ الأوامر في سجلّ الطرفية):

   ```bash
   npm run session:key
   ```

   الناتج مفتاح base64 من 32 بايت. انسخه إلى `Config Vars`، **ولا تضعه في README أو `.env` المرفوع أو رسائل الدردشة أو لقطات الشاشة**. لا تغيّره بعد الربط؛ تغيير المفتاح يمنع فك تشفير الجلسة ويحتاج إعادة ربط. لازم يكون `DATABASE_URL` و`SESSION_ENCRYPTION_KEY` جاهزين **قبل** محاولة الربط. إذا استخدمت زر Deploy to Heroku عبر `app.json`، يتم إنشاء مفتاح عشوائي من Heroku في أثناء تجهيز التطبيق، لكن راجع وجوده في Config Vars واحتفظ بنسخة آمنة.

5. انشر تطبيق container من مجلد المشروع باستخدام نفس كود نسختك. **لو الكود في فرع غير منشور، انشره لمستودعك أولًا**. في طريقة Heroku Git + `heroku.yml`:

   ```bash
   heroku git:remote -a <اسم-التطبيق-الخاص-بك>
   git push heroku HEAD:main
   heroku ps:scale worker=1 -a <اسم-التطبيق-الخاص-بك>
   heroku logs --tail -a <اسم-التطبيق-الخاص-بك>
   ```

   **ملاحظة لفروع Arena:** إن كنت تستخدم مساحة العمل هنا، لا تدفع لأي فرع غير فرع الجلسة الحالي؛ نفّذ خطوات النشر من نسختك على جهازك أو اربط Heroku بفرعك المنشور من لوحة التحكم بدل تغيير فرع المستودع هنا. `Procfile` موجود كمرجع لنسخ buildpack؛ في إعداد `container` السائد هنا `heroku.yml` هو المحدد لعملية worker. لا تشغّل web dyno؛ البوت لا يحتاج رابط موقع ولا يستمع إلى منفذ `PORT`. ينبغي أن تعرض `heroku ps` عامل `worker.1` فقط.

## ربط الرقم بكود الربط على Heroku

1. بعد ظهور `worker.1` في `heroku ps -a <اسم-التطبيق>`، أضف رقم البوت كمتغير مؤقت، ثم أعد تشغيل العامل:

   ```bash
   heroku config:set PAIRING_NUMBER="2010XXXXXXXX" -a <اسم-التطبيق-الخاص-بك>
   heroku ps:restart worker -a <اسم-التطبيق-الخاص-بك>
   heroku logs --tail -a <اسم-التطبيق-الخاص-بك>
   ```

   استخدم **رقم واتساب الذي سيرتبط بالبوت** (وليس بالضرورة رقم `OWNER_NUMBER`). لا تنشر كود الربط الذي يظهر في Logs. لا تفتح السجلات على جهاز عام، لأن الكود مؤقت وحساس. إذا طلب البوت الرقم ولم تظهر رسالة الكود، راجع صيغة الرقم/توافر واتساب على الرقم، ثم حاول بكود جديد؛ بعض نسخ واتساب تعرض اختيار الإدخال على الجهاز الثانوي وليس الهاتف الأساسي.

2. في واجهة واتساب المناسبة للربط، انتقل إلى **الأجهزة المرتبطة ← ربط جهاز ← الربط برقم الهاتف** وأدخل الكود اللي يظهر في سطر `🔑 كود ربط Black X` في السجلات. لو ما ظهر خيار الكود على هاتفك أو تغيرت الواجهة، استخدم طريقة QR المحلية أدناه بدل مشاركة جلسة أو استخدام مواقع أكواد غير موثوقة.

3. بعد رسالة `✅ Black X متصل وجاهز` تأكد إنه يرد عليك بـ `.اوامر` أو `.سرعة`، ثم **احذف رقم الربط المؤقت**:

   ```bash
   heroku config:unset PAIRING_NUMBER -a <اسم-التطبيق-الخاص-بك>
   heroku ps:scale worker=1 -a <اسم-التطبيق-الخاص-بك>
   ```

   حذف المتغير قد يعيد تشغيل العامل مرة. الجلسة المشفرة في PostgreSQL، لذلك لا يحتاج كودًا جديدًا عند إعادة التشغيل العادية. جرّب `heroku ps:restart worker` وتحقق من السجلات. **ما تشغّلش worker=2** ولا نسختين بنفس `SESSION_ID`. القفل يمنع دخول النسخة الثانية عندما يكون الأول ما زال متصلًا.

## بديل QR وربط محلي

لو عندك جهاز تاني يمسح QR، تقدر تربط البوت محليًا قبل استضافته، **لكن انتبه**: الجلسة المحلية المخزنة في `session/` لا تُرفع تلقائيًا لـ Heroku. علشان تنقلها بأمان، اربط مباشرة من Heroku بالكود أو شغّل نسخة محلية **بنفس** `DATABASE_URL` و`SESSION_ENCRYPTION_KEY`، واضبطهما على جهازك في `.env` الذي لن يُرفع، ثم نفّذ `npm run pair` بدون رقم وامسح QR من الأجهزة المرتبطة. أوقف التطبيق على Heroku (`heroku ps:scale worker=0`) أولًا، وبعد اكتمال الربط أوقف النسخة المحلية ثم أعد `worker=1` على Heroku. انتبه: بيانات القاعدة ومفتاح التشفير حساسة جدًا؛ لا تستخدمها على جهاز غير موثوق ولا تشاركها.

بدون PostgreSQL، الربط المحلي سريع للتجربة فقط:

```bash
npm ci
cp .env.example .env
# اضبط OWNER_NUMBER في .env، واترك DATABASE_URL وPAIRING_NUMBER فارغين
npm run pair -- 2010XXXXXXXX  # الكود؛ أو npm run pair لعرض QR
npm start
```

**لو ربطت محليًا بالرقم نفسه ثم حاولت ربط Heroku تاني، أوقف المحلي أولًا.** لا ترفع ملفات `session/` أو `creds.json` أو `.env` أو رابط قاعدة البيانات إلى GitHub تحت أي ظرف.

## إعداد المجموعات بعد الربط

1. أضف رقم البوت إلى المجموعة وارفعه مشرفًا من إعدادات المجموعة؛ الرفع ضروري للحذف/الطرد والترحيب.
2. أرسل من رقم المالك `.اوامر` ثم `.وضع عام` لو عايز الكل يستخدم البوت. الوضع الافتراضي خاص حتى لا يفاجئ أعضاء المجموعات بردود تلقائية.
3. جرّب `.منع_الروابط تشغيل` ثم `.منع_الروابط تعيين حذف` (الطرد إجراء أقوى؛ لا تفعله إلا عن قصد). منع الشتائم بيستخدم **قائمة كلمات تضيفها بنفسك**: `.منع_الشتائم تشغيل` ثم `.منع_الشتائم add الكلمة`.
4. للترحيب: `.ترحيب تشغيل`؛ للتخصيص: `.ترحيب تعيين أهلًا {user} في {group}`. من الأمر `.اعدادات` تابع الإعدادات.
5. الخدمات الاختيارية: احصل على `OPENWEATHER_API_KEY` من OpenWeather و`NEWS_API_KEY` من NewsAPI وأضفهما من Config Vars إن أردت الطقس والأخبار. خدمات تحميل الصور/الفيديو/الموسيقى الخارجية قد تحتاج مفاتيح أخرى أو قد تتوقف؛ لا تعد المستخدم بأنها تعمل دائمًا.

## مشاكل متوقعة وحلول

| المشكلة | الحل |
|---|---|
| `DATABASE_URL` مش موجود أو `SESSION_ENCRYPTION_KEY` غير صالح | أضف Postgres ومفتاح 32 بايت base64 قبل الربط. لا تعلن عنهما في السجلات. |
| توقف العامل بعد ظهور `SESSION_BUSY` | عندك نسخة أخرى تعمل بنفس الجلسة. أوقف المحلي أو عامل Heroku الإضافي؛ شغّل واحدًا فقط. |
| كود الربط مش ظاهر | تحقق من صيغة `PAIRING_NUMBER` الدولي، ثم راجع logs بعد إعادة التشغيل. لو انتهت مهلة الكود أعد التشغيل للحصول على كود جديد. |
| QR لا يظهر | `PAIRING_NUMBER` مضبوط؛ احذفه واستخدم `npm run pair` محليًا بدون رقم مع نفس قاعدة البيانات إذا أردت QR. |
| عاد البوت يطلب الربط بعد إعادة التشغيل | تحقق أن قاعدة PostgreSQL نفسها موجودة، وأن `SESSION_ID` ومفتاح التشفير **لم يتغيرا**. إن سجلت خروج الجهاز من واتساب، يلزم الربط من جديد. |
| البوت مش بيرد على الأعضاء | الوضع الافتراضي خاص؛ اكتب من رقم المالك `.وضع عام`. تأكد من رفع البوت مشرفًا لأوامر الإدارة. |
| أمر صور/ملصق يفشل | تأكد من تثبيت FFmpeg عبر Dockerfile وقوة الذاكرة؛ بعض APIs الخارجية تتوقف. |
| ملف صوت أو ترحيب مخصص اختفى بعد إعادة التشغيل | الملفات المؤقتة على dyno مش دائمة. رد المنشن المخصص الصغير (<1 MB) يُحفظ في PostgreSQL؛ باقي ملفات الوسائط المؤقتة تُعاد إنشاؤها عند الطلب. |
| `npm run check` أو `npm test` يفشل | استخدم Node 22 ثم `npm ci`. الاختبارات لا تحتاج ربط واتساب أو Heroku. |

## الأمان والخصوصية

- كود الربط، `DATABASE_URL`، `SESSION_ENCRYPTION_KEY`، ملفات `session/` وكل مفاتيح API **أسرار**. لا تنشرها ولا ترسلها لأي شخص؛ إذا سُربت، افصل الجهاز من واتساب وأعد الربط وغيّر المفاتيح ذات الصلة.
- حفظ الرسائل/الوسائط في بعض ميزات المشروع الأصلي (مثل مكافحة الحذف أو حفظ الحالات) حساس: شغّله فقط بموافقة المشاركين، والتزم بالقوانين المحلية وسياسات واتساب.
- Baileys مكتبة WhatsApp Web غير رسمية؛ تحديثات واتساب قد تتطلب تعديل الكود أو إعادة الربط، ولا يوجد ضمان للاستقرار أو عدم تأثر الحساب. لا ترسل رسائل جماعية غير مرغوبة.
- لم يُنشر التطبيق على Heroku ولم يُربط رقم حقيقي أثناء إعداد النسخة؛ خطوات الربط والنشر تحتاج تدخل منك.
